# Linux

On Linux, in Docker (linux/arm64 natively on an Apple silicon Mac): the test image `packaging/linux/test.Dockerfile` (the SDK image pinned by digest, fontconfig, DejaVu, libusb; runs as uid 1000, since root ignores file modes). Run it on a copy of the repository without `bin/` and `obj/` (a Linux build in a macOS or Windows checkout overwrites its `obj/project.assets.json`), with a NuGet cache mounted at `/nuget`:

```bash
docker build -f packaging/linux/test.Dockerfile -t infopanel-linux-test packaging/linux
docker run --rm --user 1000:1000 -v <copy>:/src -v <nuget cache>:/nuget infopanel-linux-test sh -c 'dotnet build InfoPanel.slnx && dotnet test InfoPanel.slnx --no-build --blame-hang-timeout 5m'
```

The Linux goldens (`Golden/linux/`, `Golden/scene/linux/`, `Golden/panels/linux/`) are generated in that image, with `UPDATE_GOLDENS=1 dotnet test InfoPanel.slnx --filter Category=Golden` as its command; the image has no CJK font, so a CJK fallback draws boxes there. SkiaSharp's Linux native (`SkiaSharp.NativeAssets.Linux`) is referenced directly, in SkiaSharp's own release line (`Directory.Packages.props`): SkiaSharp loads only a native of its own major.minor.

The Linux sensor source (`InfoPanel.Core/Sensors/Linux/`, `LinuxSensorSource`, `infopanel.linux`, polled every second; the engine's real source on Linux): hwmon channels and thermal zones read from sysfs as the normal user (`Sysfs`: `/sys`, or the full path `INFOPANEL_LINUX_SYSFS` names, logged when set; every read and listing resolved within that root first, so a link out of it, a file's or a folder's, is never followed; regular files only, opened without waiting), keyed by the Linux fork of 1.x's ids so its profiles bind them, `infopanel:/linux/hwmon/v1/{chip}/{anchor}[~{secondary}]/{channel}` and `infopanel:/linux/thermal/v1/{anchor}[~{secondary}]/temp` (`LinuxSensorIds`: the grammar, its percent-encoding, a strict parse and a build, which the 1.x import uses; re-implemented from the fork's published grammar and facts, none of its code). Each device is anchored by what identifies it, never the kernel's `hwmonN` (`HwmonAnchors`, in this order: an NVMe controller's serial with its PCI function, a disk's WWID or serial, an I²C client's adapter name and address with the adapter's owner, a USB device's ids and serial or its host and ports, a thermal zone's type with its ACPI path, the nearest PCI function or platform device (a network PHY's MDIO address as its role), else the chip's `name`); the chip drops the kernel's instance numbers (`iwlwifi_1` → `iwlwifi`). A hwmon device with no `name` of its own (the older layout) is read on the physical device its `device` link names, under the same ids. Values in °C, RPM, V, A, W, MHz and %, from `{kind}{N}_input`, or `power{N}_average` under `power{N}` where there is no input; each named by its `_label`, else its channel. Devices are found again every 10 s (a changed catalogue bumps its version; a renumbered device keeps its keys); two devices with one id are both left out, with a warning; a file the OS refuses reads `denied`, a missing one `unavailable`, never 0. Every sensor found is listed, but only those in use are read (`LinuxDemand`): read or drawn by a consumer within 2 minutes, as the weather is asked for; a listing, a status or a peek isn't a use. So a disk's `drivetemp`, whose read resets its spin-down timer, is read only while something shows it; a sensor coming into use reads from the next poll. The tests (`InfoPanel.Core.Tests/Sensors/Linux/`) build sysfs trees in memory (`SysfsKit`); no tree or link is committed. To see the source in the Linux image, write the VFD templates' hardware as a tree into a new folder (the opt-in `LinuxFixtureWriter`), and run a build of a copy with it mounted read-only:

```bash
INFOPANEL_LINUX_FIXTURE_OUT=<new folder, full path> dotnet test InfoPanel.slnx --filter FullyQualifiedName~LinuxFixtureWriter
docker run --rm --init --name <name> --user 1000:1000 -v <copy>:/src -v <nuget cache>:/nuget -v <new folder>:/fixture/sys:ro -e INFOPANEL_LINUX_SYSFS=/fixture/sys infopanel-linux-test sh -c 'dotnet build InfoPanel && dotnet InfoPanel/bin/Debug/net10.0/InfoPanel.dll --port 5390 --token <token> --data-dir /tmp/data --no-windows --no-tray --no-panels --no-browser --no-plugins --offline'
```

Then `docker exec <name> curl -s -H 'Authorization: Bearer <token>' http://127.0.0.1:5390/api/sensors` (the engine listens inside the container only) lists `infopanel:/linux/hwmon/v1/it8696/platform+it87.2624/fan1` and the rest, and `/api/sensors/values` their values (that read puts them in use: they read from the next poll, a second later).

Now Playing on Linux (`LinuxNowPlayingReader`, MPRIS on the session bus; docs/agents/sensors.md): the image has D-Bus for this check only. In one container, start a session bus (`export DBUS_SESSION_BUS_ADDRESS=$(dbus-daemon --session --fork --print-address)`), serve the fake player in the background (`INFOPANEL_MPRIS_FAKE=1 dotnet test InfoPanel.Core.Tests/InfoPanel.Core.Tests.csproj --no-build --filter FullyQualifiedName~A_fake_player_serves_on_the_session_bus_for_60_seconds &`: `org.mpris.MediaPlayer2.infopaneltest` for 60 s), and start the engine with the same address as the Linux sensor source's run line above; `curl -s -H 'Authorization: Bearer <token>' http://127.0.0.1:5390/api/sensors/values` twice, a few seconds apart, shows `infopanel:/now-playing/title` "InfoPanel Test Title", `state` `Playing` and the position moving; once the player has left the bus, `state` reads `Stopped`. `INFOPANEL_MPRIS_FAKE=1 … --filter FullyQualifiedName~MprisFakePlayerTests.The_reader` reads the fake player over the bus without an engine, and `…MprisFakePlayerTests.An_oversized_player` reads one with a title of two million bytes and a thousand repeated entries within the reader's bounds. What the reader can't bound: `Tmds.DBus.Protocol` holds each message whole before it is read and reads an error reply's text whole, so a player can make the engine hold up to what the bus lets a message be (the daemon's `max_message_size`); the reader then refuses a reply over 4 MiB and drops error texts unread. A copy made without `bin/` folders leaves out the vendored `native/mediaremote-adapter/bin/`, so `MacNowPlayingReaderTests.Every_file_pins_txt_names_is_in_the_source_tree` fails in it: exclude only the projects' `bin/` and `obj/`.

System Info on Linux (`InfoPanel.Core/Sensors/SystemInfo/LinuxProcessSampler.cs`, behind `IProcessSampler`; `AddBuiltInSources` registers `infopanel.system-info` on Linux with it, the volume stays macOS and Windows): the uptime from `/proc/uptime`, the CPUs' busy share from the first line of `/proc/stat` (none the first time, nor after a counter went back), app memory as `MemTotal` less `MemAvailable` and the compressed memory as `Zswap` (0 without) from `/proc/meminfo`; the tables list this user's processes (the `Uid` of each `status` against the engine's own; another user's are counted, their threads summed, never listed, as on macOS) by the executable's whole file name (the `exe` link, else `comm`, which the kernel cuts at 15 bytes), CPU time as `stat`'s user and system ticks at 100 a second, memory as `RssAnon` plus `RssShmem` (the whole `VmRSS` without the split), per CPU as `top` shows it; the folders are read once a round (`BeginRound`), and a process that exits while read is left out. Handle Count and CPU Utility have no Linux reading (CPU Utility reads CPU Usage). Tests: `LinuxProcessSamplerTests`, on a `/proc` the test writes into a temp folder (the sampler's `root` seam); the live check is the Linux sensor source's run line above, then `docker exec <name> curl -s -H 'Authorization: Bearer <token>' http://127.0.0.1:5390/api/sensors/values` (read it twice, a few seconds apart: the tables fill from the second poll) lists `infopanel:/system-info/uptime/formatted` and the three tables with the container's own processes.
