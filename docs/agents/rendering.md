# Rendering, simulated subscriptions and the scene runtime

- **Rendering**: `RenderService` runs one `RenderLoop` per subscribed profile, each holding a `SceneRuntime` that loads every new generation of the document (`ProfileDocument.Current`, read without the document's lock); each tick takes one `TickSnapshot` (sensors through `SensorSceneInputs`, media through the process-wide `MediaSampleCache` over the blob store), draws it once per requested scale (`FrameScale`: the sizes `api.md` specifies; above scale 1, raster media is drawn at the canvas's pixels and enlarged, `SceneDrawer.DrawMedia`, `api.md` Frame size), adds the stats overlay when the profile's `statsOverlay` is set, and hands the same `RenderedFrame` to every `IFrameSink` (the `/ws` preview, desktop windows and USB panels' `PanelSink`). A thumbnail (`RenderService.RenderOnce`, `GET .../thumbnail`) of a profile with a live loop draws the loop's latest snapshot without advancing it (no stats overlay), so at the profile's width it equals the live frame; with no loop it draws a one-off `Snapshot(now)` of the current generation.
- **Simulated subscriptions** (`sensors: "simulated"` on `/ws`, api.md "Simulated sensors"): `RenderService.Attach(sink, doc, simulated: true)` gives the sink the profile's simulated loop, a second `RenderLoop` per profile in a map of its own, shared by its simulated sinks and stopped with the last (deletes, unrenderable profiles and shutdown close its sinks too); its runtime is the service's options with `SimulatedSceneInputs` (`RenderService.SimulatedOptions`): numbers walk a step a second from its first read with 120 values of history (`Sensors/SensorWalk`: `ForUnknownKey`, mock mode's walk for keys the hub doesn't read, which the hub uses too, pinned by `SensorWalkTests`; `Around` a live reading, within a band proportional to it; its unit shown only when it is one of `SimulatedText.Units`, in the list's spelling (`SimulatedText.Unit`), else none); text and tables are made up too (`Scenes/SimulatedText`: the kind from the key's source first (the network's addresses and adapters, the drives' names, the audio devices' names), then from heuristics on the display name (`SensorSceneInputs.Catalogue`, the hub's list) and the value's shape: documentation addresses `192.0.2.x`, `2001:db8::x`, `00:00:5E:00:53:xx`, `MY-PC`, a fixed list of app names for processes (a process table's rows too, at most 12, its numbers made up each step), generic adapter, audio device and drive names, `12:00` for a time of day, System Info's uptime from a made-up start (`SimulatedText.UptimeStart`) moving as time does, else a label: the display name only when the engine names the sensor itself (`SimulatedText.IsTrusted`: `infopanel:/…`, the engine's own sources, HWiNFO and Libre), else `Text`; a table's headings likewise, else `Column N`; a number cell is a number alone, or in a table the engine names a number with a unit of `SimulatedText.Units` (in the list's spelling), any other a text cell (a plugin's cells have no types, and a shape never makes `42 A` a number); no heuristic ever lets a value through; stable per key for the loop, at most a text key per binding of a document at its limits, the key read longest ago forgotten one at a time with its turn given back), but the engine's clock, the only reading that stays real (`SimulatedText.IsRealTime`, numbers too). The session's `features` lists `simulated.text` (`ReadEndpoints.Features`) so a client knows text is made up too. `RenderOnce`, `Inspect`, `LatestSnapshot`, `IsRendering` and `LoopCount` read only the live loops (`IsSimulating` the other).
- **Scene runtime** (`InfoPanel.Core/Scenes/`, behind every output): `SceneRuntime.Load(Generation)` loads an already-checked `InfoPanel.Documents.Generation`, reusing its checked and compiled scenes by identity, so a commit costs only what it changed (one checked with other limits or support is checked again with the runtime's; `Load(JsonElement)` checks a `infopanel.document/1` into a generation first: each scene validated on its own, placeholders for the rest); snapshots carry the generation's `Rev`; `Tick(elapsed, now)` reads every input once, evaluates values, state cells (keyed by item, cell name and canonical definition) and text layout in the two phases of `spec/docs/expressions.md`, takes the media frames, and returns a reference-counted `TickSnapshot` that `Draw(canvas, scale)`, `Render`, `Bounds` and thumbnails share; `Snapshot(now)` is the one-off render (cells at init, elapsed 0). Each tick's clock carries the regional format `format` and `formatTime` use (`RegionalFormat`): the profile's `locale` (looked up with no user overrides; an unknown tag falls back and is logged once per process; the lookups and the logged tags are kept in small bounded caches), else the PC's, which `Program.cs` reads once at start-up (`PcRegionalFormat.Read`: CoreFoundation on macOS, whatever the launch environment, .NET's current culture elsewhere) and passes as `SceneRuntimeOptions.Locale`; nothing reads the process culture. Budgets at run time (work, text layouts, dashes, a time watchdog (draws counted per canvas pixel), the process node budget) draw an item as a `budget` placeholder with a diagnostic. `SceneRender` is the internal entry point for tests. Timings: `dotnet test InfoPanel.slnx -c Release --filter Category=Performance --logger "console;verbosity=detailed"`.
- **Drawing with the GPU** (`InfoPanel.Core/Output/Gpu/`; the `rendering.gpu` setting, off by default, spec/docs/api.md "Drawing with the GPU"): every draw a render loop makes (each scale, with the stats overlay) and `RenderOnce`'s thumbnails go through `RenderService.Gpu` (`GpuRendering`, one per service, applied by `Program.cs` from the stored setting at start-up and on each change, in the settings' `Changed` handler under their lock; `GET` and `PATCH` read the settings and `Gpu.Status` together under that lock, `SettingsStore.Read` and `Apply(change, answer)`, so an answer is never a new setting with the old status). Off, or while it falls back, it draws on a canvas over the loop's bitmap as before; on, on a GPU surface of the bitmap's size and type, submitted and waited for, then read back into the bitmap, so the hash, the shared `RenderedFrame` and every sink after it are unchanged and preview = panel holds on either. Every GPU draw holds the object's lock (a Skia GPU context is one thread's at a time; loops tick on the thread pool), so loops and thumbnails take turns there; no GPU object outlives a draw but the device (`IGpuDevice`: `MetalDevice` on macOS, through libobjc, each draw in an autorelease pool of its own; `D3D12Device` on Windows, through DXGI and Direct3D 12's vtable slots (`D3D12Abi`, pinned by `D3D12AbiTests`): the first adapter in DXGI's order that takes a device at feature level 11_0, never a software one or Microsoft's (vendor 0x1414: the Basic Render Driver, listed first without the software flag when no monitor is on the GPU), none left `gpu.noDevice`, the adapter chosen logged once; after each draw `GetDeviceRemovedReason` (a removal is kept, and Skia's context abandoned without freeing anything on the device, at that check or at the release, which asks first), `gpu.lost`; the engine's adapter, device and queue references released once each, Skia holding its own; on Linux none, `gpu.unsupported`). A device that can't be made is a fallback with its code (`gpu.unsupported`, `gpu.noDevice`, `gpu.failed`); it is made on a thread-pool task and waited for at most `GpuRendering.MakeTimeout` (5 s, under the settings' lock): past it `gpu.failed` with the fixed `TookTooLong`, the lock let go, and a device that comes later disposed unused, on the thread pool (a continuation queued, never run inline under the settings' lock, though the device may be made by then); one lost while drawing (any device operation throwing, its scope and surface disposal included, or a loss it reports; an exception's text stays in the log, the fallback's message is fixed) is released and that frame drawn again on the CPU, `gpu.lost` until the setting goes off and on or the engine restarts (no retry within a run); only the draw callback's own exception is thrown on, the device kept; a size it can't make a surface for draws on the CPU, logged once per size. `Draw` answers the backend that drew each frame (taken from the device before the draw: a frame read back whole whose resource purge then fails is the GPU's, its device already released) and tells the callback (the stats overlay's label is that one's), and raises the internal `Drew` with it: tests assert the backend per draw, never `Status`. Skia's GPU cache is held to 256 MiB, resources unused for 30 s freed at most every 10 s. What stays on the CPU: desktop windows' blit, panels' transforms and JPEG, PNG and NV12 encodes, media decode and the scene drawer's canvas-size pictures (Skia uploads the images it draws), `Inspect`, AI apps' `render_preview` and the preview checks, `SceneRender`, the goldens and the 1.x renderer. `GpuFrameMatchTests` (a real GPU; `INFOPANEL_REQUIRE_GPU=1` turns its skip into a failure) holds the GPU's frames to the CPU's within a bound per fixture; `GpuRenderingTests` covers the seam over a raster stand-in on every OS, and Direct3D 12's no-device and removal cases over fakes; `D3D12DeviceTests` hold the device's references and removal over fake COM objects and a context on the computer's own GPU (`GpuContextForTests`: Metal or Direct3D 12); `D3D12ProbeTests` draws all-kinds on Direct3D 12 on Windows.
