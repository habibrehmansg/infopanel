# Desktop windows

- **Desktop windows** (`InfoPanel/Desktop/`, 1.x's `DisplayWindow`): `DisplayWindowManager` (hosted service) keeps one borderless window per profile whose `profile.window.enabled` is true, each an `IFrameSink` at scale 1 (one frame pixel per backing pixel; a profile over the 16-megapixel frame cap renders smaller and the window stretches it to fill) and the frame rate setting (`frameRate`, 15 by default; a change re-times every window's loop at once, without reattaching), and applies the profile's size and its `window` (`level`: `normal`, `top` or `desktop`, `DesktopWindowStyle.Level`; `clickThrough`, `DesktopWindowStyle.ClickThrough`: clicks, scrolling and the pointer pass through to whatever is beneath, at any level, so no drag or resize reaches the window while `draggable` and `resizable` keep their values; `draggable`, `resizable`, `x`/`y` in pixels from the display matched by `display`, `strict`; 1.x's rules) as they change, undo and redo included (`DisplayWindowManagerTests`: each of the six level changes live, undo and redo, a drag keeping another client's `level` or `clickThrough`; click-through on and off live on the same window with each level, its change logged). The draft's `window.topmost` is read nowhere: in a stored document it is `unreadable`, in a checkpoint the file isn't restored, in an archive or a client's create or commit 422 `schema`, at its path. A drag or resize of the window is a `profile` commit with a `gesture:` coalescing key of its own and the revision it read as `baseRev`, read again and retried on a conflict so another client's window change is kept (undoable, saved by Save). A window's places (spec/docs/document.md, "The desktop window"): `display` is its most recent place and `spots` its places on other displays, the most recent first, at most 8; `DisplayMatcher.Place` puts it at the first whose display is connected (a monitor known by its `id`, its EDID's PNP maker and product code, `DisplayMatcher.IdOf`, when both the place and the display have one, else by name and size; macOS reads it from `NSScreenNumber`'s `CGDisplayVendorNumber` and `CGDisplayModelNumber`, Windows from `DISPLAYCONFIG_TARGET_DEVICE_NAME`'s `EdidManufactureId` (its bytes swapped into the EDID's big-endian word) and `EdidProductCodeId` when `edidIdsValid` is set (`WinDisplays.IdOf`), by GDI device name with the friendly name; that monitor back at another size than the place recorded pulls the window in to lie wholly on it, never written), and with none connected hides it (`strict`, true by default) or, not strict, shows it on `display`'s loose match or the main display, pulled in to lie wholly on it where it fits (never written); a drag or resize promotes the display it ended on (`DisplayMatcher.Promote`: the previous `display` goes first in `spots`, the same monitor's spot is dropped), and display changes still never commit. `WindowSettings` compares `spots` spot by spot, so a window committed again with the same places is no change (`DisplayMatcherTests`, `DisplayWindowManagerTests`). On macOS AppKit runs on the process main thread: `DesktopHost` runs the host on a worker and `-[NSApplication run]` on the main thread until the host stops; a window's level and collection behaviour are set together on create and on every change (`MacDesktopPlatform.Placement`): normal 0 and top floating (3), each `CanJoinAllSpaces | IgnoresCycle`; desktop one level above the desktop icons (`CGWindowLevelForKey(kCGDesktopIconWindowLevelKey)` + 1, read once), below every app window, with `Stationary` as well, so Mission Control and Show Desktop leave it in place (`MacWindowLevelTests`, macOS only, every run, no window); `setIgnoresMouseEvents:` is set with them, NO (every pixel takes clicks, transparent ones too) unless click-through, YES while it is on (no drag or resize; `setMovable:` and the style mask kept). On Windows (`Desktop/Windows/`, hand-written `LibraryImport`s in `Win32`, struct layouts pinned by `Win32LayoutTests`) the platform is `WinDesktopPlatform` on the engine's own UI thread (`WinUiThread`: a background STA thread, per-monitor DPI aware v2, started on first use, with a hidden top-level window that receives the system's broadcasts and the posted work's `WM_APP` wake (`PostQueue`: at most one waiting, each drain bounded to what was queued when it began, a wake sent for what is queued behind an action before it runs, so a modal loop runs it; after a drain that leaves work, the loop serves the input and timer messages waiting before the next wake, which Windows would otherwise take first), stopped once the host has); desktop coordinates there are physical pixels and every display's scale is 1, its `name` the GDI device name (`\\.\DISPLAY2`) and its `label` the monitor's friendly name (`WinDisplays`; the primary first, then by device name); each window (`WinWindow`) is a `WS_POPUP` with `WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE` (out of the taskbar and Alt+Tab, never activated; `WS_EX_TOPMOST` at level `top` only), up to 16,384 px, keeping its pixel size on `WM_DPICHANGED`, showing frames by `UpdateLayeredWindow` from a BGRA DIB that `DesktopFrameBlit` draws into over a floor of alpha 1/255, so transparent pixels still take clicks, as on macOS, unless click-through: then `WS_EX_TRANSPARENT` (at creation, or live as that one bit read, changed and written, flushed by `SWP_FRAMECHANGED` with no move, size or z-order change, so a top window stays topmost and a desktop-level one stays above D; `WinWindow.WithClickThrough`, `WinClickThroughTests`: the bit on any OS, the styles and order with hidden windows on Windows) sends every click to the windows beneath (a failed update tried again every 0.5 s with the same pixels until one succeeds, a retry message already waiting when one does ignored; grown again, the floor where the last frame didn't reach); display changes, resume and session connects re-match at once and 1 s later; unsupported when the window station isn't interactive (a service, a shell over SSH). Level `desktop` (`WinDesktopLevel`, documented calls only: no class names, undocumented messages, owners or parents) keeps each such window directly above the shell's desktop window D, the highest shown, non-topmost top-level window on the thread of `GetShellWindow()` (`EnumWindows`' z-order, bounded; the taskbar is topmost, File Explorer's windows run on other threads; read at each run, so an Explorer restart is followed; none: `HWND_BOTTOM`): `SetWindowPos` after the window above D, or `HWND_TOP` when that is topmost or none, nothing when only desktop-level windows lie between it and D (`WinDesktopOrder`, pure, `WinDesktopOrderTests` on any OS); it is shown in that same call (`SWP_SHOWWINDOW`), so it never shows above apps first; its `WM_WINDOWPOSCHANGING` adds `SWP_NOZORDER` to any z-order change the engine didn't make (a click, a drag's move loop, another app); while one exists, `EVENT_SYSTEM_FOREGROUND` is hooked (`SetWinEventHook`, out of context, other processes only) and each event runs the rule, which brings it back above the desktop that Win+D or Show desktop raised, and while D's thread has the foreground a 0.5 s timer on the UI thread's hidden window runs it too (the wallpaper clicked, then Win+D: no foreground change); unhooked when none is left. Live changes: to `top` `HWND_TOPMOST`, `top` to `normal` `HWND_NOTOPMOST`, `desktop` to `normal` `HWND_TOP`, to `desktop` not topmost first, then the rule. `WinDesktopLevelTests` (Windows only, every run, hidden windows with a test window playing D) hold the guard, the rule with D raised and at the bottom, each live change and the hook's lifetime. Drag and resize go through Windows' own move and size loop, as 1.4.x's did: `WM_NCHITTEST` (`WinHitTest`) answers an edge or corner within 1.4.x's resize band (10 device-independent pixels at the window's DPI, at most a third of a side) when the window is resizable, else the caption when movable, else the client, so Windows shows its own sizing cursors (the class cursor is the arrow); a press is `UserMoving` until the loop returns at the release, then `UserMoved` once, each size change in the loop `UserResized`, and a double click or the right button there does nothing. Manager state lives on the UI thread (`IDesktopPlatform.Post`). `INFOPANEL_WINDOW_TESTS=1 dotnet test InfoPanel.slnx --filter FullyQualifiedName~MacDesktopWindowTests` opens real windows on macOS (the window server's layer at each level among them; its `TheBuiltInDisplay_IsListedWithItsMonitorId` opens none: a real engine lists the built-in display's `id`), and `INFOPANEL_WINDOW_TESTS=1 dotnet test InfoPanel.slnx --filter FullyQualifiedName~WinDesktopWindowTests` on Windows, in the signed-in user's session (it also logs `ShowFrame`'s timings); skipped otherwise. `WinUiThreadTests` and `WinWindowInputTests` (Windows only, every run) use hidden windows only; `WinDesktopWindowTests`' drags and its desktop case (not topmost, below a normal window, still after a click) move the real mouse (`SendInput`), so the session must be connected and unlocked; its click-through case reads the window under a point (`WindowFromPoint`: the window beneath while on, the panel while off) without moving the mouse.
