# The REST API and the preview socket

- **REST** (`/api/...`, exactly `spec/docs/api.md` and `commit.md`; bodies are the `InfoPanel.Spec` model written with `SpecJson.Options`): session (`protocol: 2`, `instance`, `features` (`plugins`, always), `formatSupport` by format string (`infopanel.document/1`, `infopanel.scene/1`, `infopanel.archive/1`), each with its version, capabilities and limits (`SpecLimits.FormatOf`), `platform`, `dataDir`, `locale` (the PC's regional format read at start-up); for bug reports `engineBuild` (the commit the engine was built from, `-dirty` with uncommitted changes, `unknown` without git or a repository: recorded at build time by `RecordEngineBuild` in `InfoPanel/EngineBuild.targets`), `osVersion` (macOS's product version, Windows's major.minor.build, Linux's kernel release), `arch` (the engine process's) and `started` (the run's start, `EngineRuntime.Started`); `mock`, the run's mock mode or a replayed recording (`--replay-sensors`); `media.providers`, the media providers configured on the engine, `http`, `now-playing`, `plugin`, and `rtsp` with FFmpeg), fonts, sensors (by key, with `status` and `type`, `number`, `text`, `table` or `image`, from the same hub read, and an image sensor's `provider`, `now-playing` or `plugin`, the media provider that draws it) and values, the sensor sources' states (`GET /api/sensors/sources`: every source the hub runs, in its order, with its state, reason and sensor count; `SensorHub.SourceStates`; Libre's entry with the PawnIO driver, `driver`, and its install, `POST /api/sensors/sources/libre/driver`, session token only: spec/docs/api.md "The PawnIO driver"), the engine settings (`Api/SettingsEndpoints.cs`, session token only: `GET /api/settings` answers `engineSettings`, every value with the run's `version` and the file's `status`; `PATCH` checks the body (409 `settingsStatusProblem` first when the file couldn't be read, then `settingsRequestBytes`, JSON and the schema) and hands it to `SettingsStore.Apply`, whose refusals are 422), the recent log entries (`Api/LogEndpoints.cs`, session token only: `GET /api/logs?after={seq}` answers `logPage`, `RecentLog`'s kept entries newer than `after`, oldest first, with `latest`, the run's newest `seq`, read together; an `after` that isn't 0–2^53−1 in decimal digits, or given twice, is 400), opening the engine's folders (`Api/FolderEndpoints.cs`, session token only: `POST /api/folders/{folder}/open` hands the data folder (`data`), `logs/` (`logs`) or `plugins/` (`plugins`, created when absent, never through a link: a link there is 500) to `IFolderOpener`, `Hosting/FolderOpener.cs`: `open` on macOS, `explorer.exe` on Windows, `xdg-open` elsewhere, the folder its one argument, refused when it isn't a folder; a folder started under a second ago, or a request while four file managers haven't exited, starts nothing and is answered 204, and no request waits on the child; any other name is 404, and an opener that throws is logged and answered 500; every test engine (`EngineFactory`) has a recording opener instead, so no test opens a file manager), the plugins (`Api/PluginEndpoints.cs`, docs/2.0/plugins.md: `GET /api/plugins` every token's, each package's state, plugins, actions, CPU, memory and newest errors, never a setting's value; the session token's on and off, reload, a package's folder opened, a listed action's state read and the action run when its state allows (no other method; 409 when it doesn't) and a plugin's settings read and changed through its host as it runs, each call to a host bounded at 10 s; 404 for a folder naming no package, every one under `--no-plugins`), the displays (`Api/DisplayEndpoints.cs`, every token: `GET /api/displays` answers `displayList`, read after each request comes on the desktop thread (`DisplayLister`: one listing posted at a time, shared by the requests that come while it waits, and skipped when none waits for it any more), each request waiting up to 5 s on the host's `TimeProvider` (then, or when the platform throws, logged and 500), the primary first, each display's `name`, `width`, `height`, `x` and `y` exactly `DisplayMatcher.TargetOf` (what `window.display` takes, so filling a display is one `profile` commit), its `label` (`DisplayInfo.Label`, else its name, cut at 256) and `scale`; `supported` false and none while `DisplayWindowManager.Enabled` is false: `--no-windows` or `NullDesktopPlatform`), profiles (list with statuses `ok`/`unsupported`/`unreadable`, create empty or from a document under a client-chosen id, duplicate, delete), a profile's document (`GET /api/profiles/{id}`: `documentResponse`), export (`GET …/document`), thumbnail, commit, undo, redo, revert, save, blobs (`POST`, `HEAD`, `GET /api/blobs/{id}`), integration tokens (`POST`, `GET /api/tokens`, `DELETE /api/tokens/{id}`; session token only), the paired clients (`GET /api/pairings`, `DELETE /api/pairings/{id}`; session token only) a pairing code's exchange, a pairing pass's and the pairing proofs (`POST /auth/pairing/code`, `/pass`, `/challenge`, `/proof`, no token; `CLAUDE.md`'s Security model; the pass: `docs/agents/service.md`), the profile archive (`spec/docs/archive.md`: `GET /api/profiles/{id}/archive` builds `.infopanel2` in a temp file, 409 for a profile that isn't `ok` (`profileStatusProblem`) or an archive its import would refuse (`exportProblem`); `POST /api/import/archive` opens one, manifest first, and stores its blobs; a client creates the profile), and the 1.x import (`spec/docs/import.md`, `Api/ImportEndpoints.cs`): the migration's state and run-once record (`GET`, `PUT /api/import/v1`; the record's optional `devices`, the client's 1.x panel device outcomes (`family`, `deviceId`, `deviceLocation`, the saved device's `id`, `outcome`), stored as given and answered only when the request had it, the engine mapping no 1.x device field), and a 1.x folder profile or a `.infopanel` file read into an envelope that stores its images as blobs (`POST /api/import/v1/profiles/{v1Id}`, `POST /api/import/v1/archive`, one at a time behind `ImportGate`, an archive body buffered to a temp file within `archiveBytes`, else 413); a client creates profiles from the envelopes. A request on a profile is checked in order: 404, 409 `profileStatusProblem`, 422, then its own checks (409 `exists`, conflicts, `expired`). Errors are `application/problem+json`. The step-1 editing API (`/api/kinds`, `items/*`, `PATCH` profile, `.infopanel` import and export) is gone.
- **`/ws`**: the client subscribes to a profile at a scale and fps, and an `encoding` (`png`, the default, or `h264`; `keyframe` asks the next video frame be a keyframe); the server sends `hello` (`protocol: 2`), `doc` events (`docEvent`: `rev`, `dirty`, `canUndo`, `canRedo`, `recovered` while set; a coalesced latest-state slot, after every change from any client, and after the process history budget evicts the document's steps), `profiles` events, `settings` events (`settingsMessage`, the settings' `version` after a change to the stored settings; only to sockets of the session token, which alone reads them; this engine sends it ahead of `profiles`, an order the API leaves unspecified), and binary frames (`IPF1`, the `frameHeader` of `api.md`: `rev`, `tick`, `frameId`, `scale`, sizes and `itemBounds` from one tick snapshot, each with its item's first media problem of the tick, `media`, `encodeMs` and `skipped`, then the payload: a PNG, or for an `h264` subscription an H.264 access unit, with PNG frames that say why (`fallback`) where it can't be video). A frame is sent only when pixels, bounds (`media` included) or revision changed; ticks never go down within a subscription.
- **An image sensor's picture** (`GET /api/sensors/image?key={key}&ref={ref}` in `Api/ReadEndpoints.cs`, the `sensors.image` feature, every token's; spec/docs/api.md "Sensor pictures"): the bytes `SensorHub.TryGetImage` gets from the key's source, held to `MaxImageBytes` (8 MiB) and inspected by `MediaValidator.Check` (a PNG, JPEG, GIF or WebP within the media limits, else 404), answered as they are with that format's media type and `Cache-Control: no-store`; 404 `problem` for every miss (no image sensor, no picture under the reference, a cover held only as an address), 400 for a `key` (at most 512) or `ref` (at most 2,048) absent, empty, given twice or too long; it reads no sensor (nothing started), decodes nothing and logs nothing of the reference. Tests: `SensorImageEndpointTests`, the tour.
