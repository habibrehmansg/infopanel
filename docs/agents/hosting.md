# The engine's command line

`--fresh` is a dev and test flag that wipes the whole data folder before start-up: it needs `--data-dir`; it refuses a filesystem root, the home folder or a folder above it (checked on the path as given and on its real path, links resolved) and a folder with any top-level entry the engine doesn't write (`store.json`, `profiles.json`, `tokens.json`, `pairings.json`, `settings.json`, `service-credential`, `service-credential.bin`, `profiles/`, `blobs/`, `fonts/`, `logs/`, `plugins/`, `plugin-settings/`, `plugin-state.json`, `devices.json`, `runtime.json`, `engine.lock`, step-1's `profiles.xml` and `assets/`, the 1.x migration's `import-v1.json`, their write temp files); otherwise it deletes everything in the folder except `engine.lock`, including whatever is inside those engine folders (user-added fonts too), removing links without following them. The web root is `--web-root <dir>` as given, else `{BaseDirectory}/wwwroot` when it has an `index.html`; with neither the engine serves the API and `/ws`, and a plain-text "no web client installed" page on unmatched non-file paths outside `/api`, `/ws` and `/auth` (file-like paths such as `/index.html` or `/missing.js` return 404). `--mock` is mock mode: the mock sensors instead of the platform's real ones, and simulated values for well-formed keys no source handles; without it unknown keys are `unavailable` (the `dev` launch profile and every test host pass it). Exit codes: 0 clean, 1 fatal (a data folder whose marker this engine can't honour included), 2 bad arguments (a bad built-in web client origin included), 3 data folder in use: a **second launch** (no `--no-browser`) first asks the engine that holds the folder, over its local channel as a `launch` companion, to open the editor, and prints "InfoPanel is already running; opened the editor" (`Hosting/SecondLaunch.cs`); when nothing answers on the channel (an engine stopping closes it before it lets go of the folder, which it keeps through its clean-up), any launch waits for the folder up to 5 s (`SecondLaunch.HandOff`) and starts once it is free. An `infopanel:` link (docs/2.0/desktop-shell.md, "Opening the editor") is accepted only as the only argument, any case, and never read (`EngineOptions.FromLink`): on a held folder a second launch; an engine it starts opens the editor once it listens; with anything else it is an unknown argument, exit 2. On macOS the bundle declares the scheme and the app delegate, set before the AppKit loop runs, answers `application:openURLs:` as opening the app again; the Windows installer registers it per machine. The sign-in link (`/auth/<token>`, printed only when a web client is served here, since it leads nowhere otherwise) and each `--allow-origin`'s pairing link go to the console only (the file log and the recent entries get them with `<token>`). `--allow-origin`'s default is the origin a release build carries (the MSBuild property `InfoPanelAllowOrigin`, recorded as the assembly metadata `InfoPanel.AllowOrigin` by `InfoPanel/WebClientOrigin.targets`; none in a build from source), checked as the flag is; any `--allow-origin` replaces it.
