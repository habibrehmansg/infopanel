# Opening the editor, the menu-bar item and updates

- **Opening the editor** (docs/2.0/desktop-shell.md, "Opening the editor"): the engine never opens a browser by itself, however it was started; only the menu's Open Editor (and Edit from Another Computer…, and the row of who is signed in) and a second launch do, through `EditorOpener`. What opens is `EngineRuntime.EditorLinkFor`: with no web root served and exactly one cross origin allowed, that origin's code link (a release build's configured web client), `{origin}/#engine=http://127.0.0.1:{port}&code={code}` with a one-time pairing code minted for each open (`PairingCodes`, `CLAUDE.md`'s Security model) and never the session token; otherwise the sign-in link. A link to a page of the client (`EditorLinkFor`'s `then`, only one of `EditorRoutes.Known`, today `#/settings/account` for Edit from Another Computer… and the row of who is signed in; any other throws before a code is minted) adds `&then={page, URL-encoded}` to the code link, or `?then=` to the sign-in link, whose redirect (`GET /auth/{token}`) hands on only a page it knows, once, as the engine spells it (`/#token=…&then=…`), and leaves any other out. The console still prints each cross origin's token link (`PairingUrlFor`), for scripts and `--token` runs: it connects for that run and never pairs. `BrowserLauncher` writes the link into a private redirect file (`RedirectFiles`: `{run}/{hash16}.open-{random}.html`, 0600, in the 0700 run folder, an HTML refresh to the link; on Windows the folder and each file get a protected access list granting only this user, `WindowsPrivateFiles` behind the seam `IWindowsSecurity`, and an existing folder that lets others in or inherits its list is made private or refused) and hands only the file's path to the browser, so the token is in no process's arguments; a pairing link goes to Chrome first (macOS `open -b com.google.Chrome`, Windows `chrome.exe` from App Paths, Linux `google-chrome-stable` or `google-chrome` on the `PATH`), then the default browser; a sign-in link to the default browser. The default browser is the system's for `http` links (`DefaultBrowser`: Launch Services' app, run as `open -a {app}`; the `http` association's command, the file unquoted after Chrome's and Edge's `--single-argument`, which takes the rest of the line as it is (quoted, Edge opened `http://"c/…`); `xdg-settings`' desktop entry's `Exec`), named in the command so the file never reaches the `.html` handler; only when it can't be told, the file's association (`open`, the shell, `xdg-open`). A browser started directly that exits with an error within 2 s failed, and the next is tried. Each file is removed 2 minutes after it is written, at the engine's stop, and a crash's leftovers at the next start.
- **Menu-bar item** (`InfoPanel/Shell/`, docs/2.0/desktop-shell.md): on macOS, unless `--no-tray`, an `NSStatusItem` with the logo's glyph (`ShellGlyph`, drawn at start as a template image) whose tooltip is the engine's address and whose menu, rebuilt from `ShellMenu.Build` each time it opens (a `ShellState`: lines with stable ids, kinds, check marks and submenus; macOS's words, which another platform maps by id), is the header "InfoPanel" (bold, an attributed title) and "Running · {version}" (secondary colour); who is signed in, one clickable row that opens the editor at its sign-in settings (`EditorRoutes.AccountSettings`): a round initial (`ShellInitial`, the item's image), the name and beneath it the email in the secondary colour (an attributed title), the email alone without a name, "Not signed in" (secondary) with "Sign In…" beneath (the label colour, `ShellMenuItem.DetailIsAction`) without a credential or once the service refused it, no row while the holder isn't known (`ServiceHolder` (`InfoPanel.Core/Service/`), run by `ShellService` while the icon can show, asks the configured service `GET /svc/v1/holder` through `ServiceClient` with the credential, at start, on each change of the credential or the address (`ServiceCredentials.Changed`) and every 6 h after an answer while one is held; after a failed ask after 1 min, doubling, or a longer `Retry-After`, at most 6 h, and at once on a network change (`NetworkChange.NetworkAddressChanged`, followed by `ShellService`; one during an ask kept for its end, asked at once if it fails; one such probe per failed ask), an ask sent before a change of the credential or the address scheduling nothing; a failure of the task itself waits for the next change), 15 s and 4 KiB bounds; the name, else the email, and the email beside a name, control characters dropped, the name past 40 characters shortened, the email past 32 in its middle, kept in memory under the credential's generation (`ServiceCredentials.StateAndGeneration`) so a late answer for a credential since replaced shows for none, a failure keeping the same credential's; never stored or logged; the menu reads a snapshot published after each change by one publisher at a time (on the pool after a change's notification, which may come under the credential's lock and so never publishes itself; on the task after an ask), never the credential's lock); Open Editor; Edit from Another Computer… (the editor at the same sign-in settings, where another computer is set up to edit this one); Show on Desktop (only while desktop windows are on: each `ok` profile in the library's order, checked when its window is on, "No Profiles Yet", past 20 "More in the Editor…"); Click-Through right under it (the same while: each of those first 20 whose window is on, checked while `window.clickThrough`, "No Windows Shown" when none); Show Data Folder in Finder, Open Logs Folder (`IFolderOpener`), Copy Engine Details (`EngineDetails`: version, protocol, system, build, started, OS version, architecture, address, data folder with `~`, the home folder matched as its volume compares names (`EngineDetails.CaseRule`: on macOS as the home folder's volume says, `pathconf`'s `_PC_CASE_SENSITIVE`, asked once, without case when it can't be asked; without case on Windows; with case elsewhere); never the token, a link, a profile or who is signed in; `IShellPlatform.CopyText`, a default that does nothing, `NSPasteboard` on macOS); Quit InfoPanel. `ShellService` shows it once the server listens and removes it when the engine stops; Open Editor opens the editor (`EditorOpener`, above); a Show on Desktop line (`desktop:show:{id}`, `desktop:hide:{id}`: the state opposite the check it showed) commits `window.enabled`, and a Click-Through line (`click-through:on:{id}`, `click-through:off:{id}`) `window.clickThrough`, as the editor's switches do, at the revision read and read again on a conflict, saved at once at that revision when the profile was clean before it (`ProfileDocument.Commit(…, out wasClean)`), else left unsaved; Quit stops the engine at once unless a profile has unsaved changes, when an `NSAlert` names them (three, then how many more) with Open Editor (default), Cancel and Quit Without Saving; a system quit (`applicationShouldTerminate:`, logout) answers "later" once the item has shown (before, "now", as AppKit does without a delegate), stops the engine without asking, and lets the quit go on once the host has stopped. The AppKit loop runs when windows **or** the item are on (`DesktopHost.Choose`); off the main thread (every test host) and on Linux the shell is `NullShellPlatform`. On Windows, unless `--no-tray`, a notification-area icon on the engine's UI thread (`Shell/Windows/WinShellPlatform`, owned by `WinUiThread`'s hidden top-level window through a message hook; whatever thread starts the engine; not when the window station isn't interactive): the app's coloured logo (`WinTrayLogo`: `Images/logo.png`, embedded) at the taskbar's DPI, the same on a light or dark taskbar (redrawn when the scale changes), tooltip "InfoPanel {version}", a click (`NIN_SELECT`, not twice within a double-click) runs Open editor, a right click shows the model's menu in Windows' words by line id (`WinShellText`: "Open editor" bold as the default item, "Edit from another computer…", "Show on desktop" and "Click-through" submenus (`MF_POPUP`) with their check marks, "Open data folder", "Open logs folder", "Copy engine details" (the clipboard as `CF_UNICODETEXT`, `WinClipboard`), "Exit") with the platform's own Start when I sign in above Exit (`WinTrayMenu`), added again on `TaskbarCreated`; Start when I sign in is the `InfoPanel 2` value under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` (not 1.x's `InfoPanel`, which 1.4.x deletes at every start; `WinStartup`, read when the menu opens, off when Task Manager's StartupApproved switch is); Exit's prompt is a `TaskDialogIndirect` ("Exit InfoPanel?", Open editor, Exit without saving, Cancel), which needs Common Controls 6 from `InfoPanel/app.manifest` (under the `dotnet` host, `WinCommonControls` activates it from the same manifest embedded in `InfoPanel.dll`); signing out or shutting down (`WM_ENDSESSION`) stops the engine without asking and holds the session's end until the host has stopped, at most 4 s (`WinTray.SessionEndWait`). `WinTray` holds the logic with no Win32 (`WinTrayTests`, `WinTraySystemTests` on any OS through a fake); `WinShellPlatformTests` pins the structures and, with `INFOPANEL_SHELL_TESTS=1` on Windows in a signed-in session, adds a real icon. `INFOPANEL_SHELL_TESTS=1 dotnet test InfoPanel.slnx --filter FullyQualifiedName~MacShellTests` adds a real item (skipped otherwise).
- **Updates** (`InfoPanel.Core/Updates/`, docs/2.0/desktop-shell.md "Updates"): `UpdateCheck`, run by `ShellService` while the icon shows, GETs the engine repository's public releases on GitHub (`UpdateCheck.GitHubFeed`) with only `Accept`, `X-GitHub-Api-Version` and `User-Agent: InfoPanel/{version}` (no token, cookie, machine name or trace header; `If-None-Match` with the last `ETag`, in memory), `https` only (`http` on loopback for tests), no redirect, 15 s, 1 MiB; 30 s after the icon shows, then a day of wall-clock time after the last answer, looked at hourly; an hour after a failure; GitHub's `Retry-After`/`X-RateLimit-Reset` (1–24 h) on a 403 or 429. Never for a development build (`ReleaseFeed.IsDevelopmentBuild`: a pre-release starting `dev`, so every source build and test engine), and with `--offline` only a loopback feed; `INFOPANEL_UPDATE_FEED` replaces the address (development). `ReleaseFeed` (pure) reads `tag_name`, `draft` and `prerelease` only and offers the highest SemVer 2 version above the engine's that its channel takes (a pre-release build: pre-releases and releases; a release build: no `-`; never GitHub's flag, drafts or 1.x), its page built from the tag. The menu's line under the version: "Update Available: InfoPanel {v}…" (`ShellMenu.UpdateAvailable`, opens the page through `BrowserLauncher`) while `UpdateCheck.Latest` is set, else "Check for Updates…" (`ShellMenu.CheckForUpdates`, at most one check every 10 s, answered through `ConfirmAsync`: available, Download/Later; up to date; couldn't check); neither when the check is off; Windows' words in `WinShellText`.
- **The update notification** (docs/2.0/desktop-shell.md "Notifications"): `IShellPlatform.Notify(ShellNotification, clicked)` (a default that does nothing; Windows a balloon on the tray icon, `NIF_INFO` with `NIIF_USER | NIIF_RESPECT_QUIET_TIME`, shown as a toast, title ≤ 63 and text ≤ 255, its click `NIN_BALLOONUSERCLICK`; macOS `UNUserNotificationCenter` in `Shell/MacOS/MacNotifications`, only from the app bundle (without a bundle identifier the centre would end the process, so it is never asked), permission asked the first time there is something to show, one identifier so a newer replaces an older, blocks through `ObjC.GlobalBlock`, a centre that can't be set up logged once and never thrown, and after `MacNotifications.Stop` (the icon's `Remove`) nothing submitted, a late permission answer included); each platform keeps only the newest notification's click. `ShellService` follows `UpdateCheck.Changed(UpdateTrigger)` while the icon shows: a version offered above every one notified before (SemVer 2, `ReleaseFeed.Compare`) is first recorded in `updates.json` (`InfoPanel.Core/Updates/UpdateNotices`: `{"format":"infopanel.updates/1","notified"}`, the highest version attempted, at most 256 characters; `Remember` answers false when the write fails, and nothing is shown; a bad file, a lone surrogate included, is logged and counts as none), then, unless Check for Updates… found it (`UpdateTrigger.Menu`: its prompt answers, the version still recorded), gets "InfoPanel {v} is available" / "Click to see what's new and download it.", whose click opens that version's release page (the address captured then; with one live click, the newest notified) and nothing else. So each version notifies at most once, ever, and none for a development build or when up to date. Tests: `ShellUpdateTests` through `FakeShellPlatform`'s `Notify` (records each, keeps the newest click), `UpdateNoticesTests`, `WinTrayTests`, `MacNotificationTests`; a real notification is a hand check from the bundle.
